# 数据隐私与公开发布要求

适用范围：Bitget 自选标的监控、dsh 研究与对话、LangGraph 状态管理，以及本项目 GitHub 交付。

当前状态：本文是实现及验收要求，不代表相关运行时控制已经实现。仓库先私有，只有用户明确要求后才可公开。私有仓库也不能保存真实密钥或个人运行数据。

## 数据分类及去向

| 数据 | 本地保存 | GitHub、CI 与发布包 | 外部模型 |
| --- | --- | --- | --- |
| API Key、Secret、Passphrase、模型密钥、访问令牌 | 环境变量或受保护的凭据存储 | 禁止；CI 只通过专用 Secrets 注入 | 禁止进入提示词、工具结果与附件；模型认证凭据仅发往配置的服务认证接口 |
| 账户标识、余额、持仓、订单和交易历史 | 第一版不采集 | 禁止 | 第一版不发送 |
| 自选列表、个人阈值和研究偏好 | 本地私有配置 | 仅虚构示例 | 分析所需的标的、阈值可按最小范围发送；不附带完整个人配置 |
| 行情、K 线和交易品种信息 | 缓存和研究证据 | 只提交小规模测试样例；真实批量数据不随项目发布 | 可发送完成研究所需的片段 |
| 用户对话、研究记录、目标及待验证判断 | 私有会话和数据库 | 禁止；演示使用合成内容 | 使用云模型时，发送必要消息或摘要；用户输入默认按可能含个人信息处理 |
| 检查点、消息队列、触发脚本、dsh 会话 | 私有运行目录 | 禁止 | 仅发送所需业务状态；不上传完整数据库或会话目录 |
| 日志、错误、诊断和截图 | 脱敏后有限保留 | 只允许人工确认的脱敏材料 | 默认不发送完整日志 |
| 代码、文档、依赖锁文件和配置模板 | 可以 | 可以，发布前扫描 | 开发工具使用时仍应排除凭据和运行数据 |

公开可查询的行情不等于可任意再分发。交付以接入代码和合成测试数据为主；批量再发布数据前单独核实数据源使用条件。

## 存储布局与访问边界

- 使用项目内 `runtime/` 保存数据库、日志、报告、等待脚本及独立的 dsh home；使用 `config/private/` 保存真实监控配置。
- 固定项目自己的 dsh home，避免读取用户其他 dsh 项目的会话、凭据和记忆。研究工作区只包含当前任务需要的数据。
- `.env.example` 只含空值或明显占位符；真实 `.env` 不进入 Git、构建上下文或诊断包。
- 文件访问仅授予运行账户和必要管理员。忽略文件不会加密文件，也不会阻止拥有操作系统权限的其他进程读取；如需静态加密，应配置系统磁盘或专门存储加密，不宣称 SQLite 默认加密。
- 等待脚本可能含个人标的和策略，应按私有运行数据管理。脚本只获得行情快照和受限计算能力，不继承 Bitget Secret、模型密钥或 GitHub 令牌。

## 外部传输和模型隔离

1. 默认仅访问配置的 Bitget 和模型服务；首次配置明确列出实际模型提供方、目标地址及将发送的数据类型。不得把“本地运行”描述成“数据不会离开电脑”。
2. 研究进程不继承整个宿主环境。使用最小环境白名单；交易所凭据只属于数据接入组件，模型凭据只属于模型传输组件。模型可调用的 shell、文件和网络工具不得读到凭据存储。
3. 审计 dsh 默认工具、遥测、崩溃上报及 SDK 日志。未经配置不启用第三方追踪平台、远程遥测、Webhook 或外部通知；无法确认关闭时不得宣称无遥测。
4. 发送模型前裁剪数据，移除认证字段、账户标识及无关个人信息。不能只依赖模型遵守“不要泄露”提示词，也不能假定简单正则能识别所有秘密。
5. 对话 agent 只能读授权的研究摘要；其反馈进入持久 inbox。来自新闻、工具结果或用户粘贴材料的指令不能扩大工具访问范围。
6. 云模型服务的数据保留、训练使用和删除能力由具体提供方与账户设置决定，配置时核实，不能承诺本地删除会同步删除供应商副本。

## 日志与诊断

- 采用字段白名单记录时间、事件 ID、市场类别、状态、耗时和错误类别。默认不记录完整 HTTP 请求/响应、提示词、认证头、环境变量、对话正文或 dsh stdout/stderr。
- 异常内容中的 URL 参数、Authorization、Cookie、签名和秘密字段必须过滤；必要时将原始错误替换为受控错误码。
- 调试模式必须显式开启、有到期时间，输出仍保存到私有目录。问题反馈和诊断导出采用文件白名单，不递归打包工作区。
- 子进程参数中不传密钥，避免进程列表和错误日志暴露；研究输入使用任务文件或协议消息。

## 保留、删除及备份

以下是可配置的初始默认值，运行实现必须执行清理：日志 7 天，行情缓存 30 天，已完成任务检查点和已消费消息 30 天，研究报告与会话 90 天。活跃目标所需最小证据及未完成触发器保留至任务结束，再进入相应清理周期。

提供按任务、按标的和清空个人运行数据的删除入口，覆盖业务表、检查点、inbox、dsh 会话、报告、触发脚本及相关索引。不能只删界面记录。SQLite 删除不等于存储介质上的安全擦除；涉及 WAL、文件系统快照或 SSD 时不承诺不可恢复。

默认不创建外部备份。启用备份时使用加密和明确保留期，删除清单同步适用于备份，到期淘汰前向用户说明仍存在副本。恢复备份不得重新激活已撤销的目标、令牌或等待脚本。

## GitHub、CI 和从私有转公开

- 主仓库只纳入自己的源码、文档、测试及示例。dsh 保留上游许可证与来源，后续通过固定提交的 submodule/fork 交付；其独立 Git 仓库也需要单独扫描，父仓库 `.gitignore` 不能保护其提交。
- 提交前和 CI 执行密钥扫描；公开前扫描全部 Git 历史、所有计划发布的分支及标签，以及 Release、Actions 日志/产物、缓存、截图和文档。
- 单元测试使用合成数据和模拟服务，不需要真实凭据。真实接口测试单独显式启用；只使用最小权限测试凭据，不给来自不可信 PR 的代码注入 Secrets。
- 不缓存或上传 `.env`、数据库、dsh home、用户配置及运行目录。发布包和容器使用明确文件白名单，`.gitignore` 不是打包安全边界。
- 项目公开不自动公开用户的 dsh fork 或其全部历史；分别审查可见性与可访问性，保证接收者可以拉取固定源码。
- 真密钥一旦进入 Git 或 CI，先撤销/轮换，再清理历史和产物；删除最新文件或继续保持私有都不能替代轮换。

## 交付验收

- Git 忽略测试覆盖凭据、数据库及 sidecar、真实配置、日志、报告和 dsh home；模板和源码仍可跟踪。
- 使用人工构造的秘密标记测试请求、异常和模型工具输出，确保不会出现在日志、模型输入、诊断包及 CI 产物。
- 验证研究工具与等待脚本无法访问凭据；对话 agent 无法读其他任务的私有会话。
- 验证保留期清理、按任务删除、重启与备份恢复后的撤销状态。
- 公开前确认无真实个人数据，检查所有仓库和产物，并取得用户明确的公开指令。
