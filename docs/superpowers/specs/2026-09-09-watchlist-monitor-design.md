# Bitget 自选标的长期监控设计

日期：2026-09-09。状态：基础方向已确认；补充用户提出的休息、持续观察和并行对话需求，尚未实现。

## 目标与边界

在本地运行一个持续观察指定 Bitget 交易品种的后端。使用 LangGraph 管理研究流程，使用 DeepSeek Harness（dsh）执行研究。用户通过配置文件维护自选列表，记录品种代码和市场类别，避免现货、合约和股票相关产品混淆。空列表允许完成配置检查，但运行监控必须提供至少一个有效品种。BTCUSDT 等仅作为文档示例，不代表用户选择。

第一版覆盖行情观察、异常研究、持久记录、本地提醒和每日简报；不包含交易执行或新闻接入。仅依据行情分析，不能把价格变化解释为已证实的新闻因果。

## 方案选择

采用每 60 秒 REST 轮询：适合少量自选标的，便于调试和恢复。WebSocket 可降低延迟，但增加重连和补数据复杂度，留待需要秒级观察时增加。轮询周期和规则参数均可配置。

## 架构与数据流

Python 常驻进程按计划收集行情与已收盘 K 线，验证数据新鲜度，计算确定性规则，将异动写入 SQLite 事件表。采集与研究通过持久队列解耦，模型调用不阻塞行情轮询。

LangGraph 流程为加载事件和历史记录、准备证据、调用 dsh、验证研究结果、保存结果和后续观察、生成本地通知。使用磁盘检查点；事件数据库管理待处理、运行中、成功和失败状态。启动时恢复过期任务租约，重试有上限。

dsh 使用完整 Git 源码检出，存放在 vendor/deepseek-harness，保留上游远程和历史，以支持本地功能开发。此前的单次 headless 方案不足以承担研究中对话，主接入改为基于源码构建的 SDK profile 与持久会话，具体协议依据检出的源码核实；headless 仅用于单次研究冒烟验证。模型凭据从本地环境读取。每次研究有独立工作目录、输入证据文件和限定格式输出，设置超时与并发上限。首版研究并发为 1，对话通道独立；后台研究预算初始为每日 20 次，超出预算仍采集和记录事件，交互模型消耗独立记录并有明确上限。Bitget 凭据和模型凭据分别配置。

研究输出包含摘要、证据引用、限制、后续观察条件；引用必须对应输入数据。输出解析失败或模型配置缺失时保留待研究事件，不生成伪造分析，也不把原始错误标为研究成功。跨日连续性由持久会话以及数据库中的历史结论、目标版本和待复查事项提供。

## 休息、持续观察和并行对话

每个研究任务有 THINKING、SETTLING、RESTING 三个阶段；ERROR 和 PAUSED 单独记录，不能混同为正常休息。行情采集与对话入口不依赖研究任务处在哪个阶段。

THINKING 阶段形成判断、目标及可验证的反证条件。研究 agent 调用注册等待工具，生成版本化的等待触发脚本与结构化描述，包含标的、条件、数据窗口、到期时间、唤醒原因及所属目标版本。基础价格、成交量和时间条件从受限表达式生成脚本，执行器只提供行情快照和受限计算能力，禁止任意系统命令；复杂自定义脚本后续通过独立隔离执行器扩展。执行失败显式报错，不解释为条件未触发。

注册等待后先进入 SETTLING，即用户要求的持续观察阶段。默认观察 15 分钟、每 5 分钟一次有界复评，期限和频率可配置。等待条件从注册成功即生效，因此这段时间既可以被触发唤醒，也可以主动思考目标是否合理。复评检查新证据和反证，而不是机械重复原结论。数据不足时记录未知，不当作目标正确。若更新目标，产生新版本，撤销旧等待并注册替代条件；观察结束后进入 RESTING。

RESTING 阶段结束模型调用，保留状态，由外部执行器继续运行等待脚本。触发事件、到期复查或用户输入可以再次唤醒。先持久保存检查点与等待订阅，再进入休息，订阅从已保存的数据游标开始检查，以避免注册与休息间丢信号。恢复时重新装载有效订阅；唯一事件键、目标版本检查及任务租约避免重复唤醒或旧条件唤醒新目标。

对话使用独立 dsh 会话或对话 agent，可在研究运行中响应用户，也可由研究 agent 提出问题。对话读取研究摘要和可公开证据，不暴露内部推理文本。用户反馈写入持久 inbox，区分观察事实、用户观点和明确指令；研究 agent 在模型步骤或工具调用边界消费。普通反馈不打断当前工具操作；用户停止或撤销指令优先处理并取消可取消任务。模型请求进行中不直接修改其已发送的上下文。

需要用户答案的研究分支可以暂停，其他独立监控继续；未回答不会被解释为同意。对话会话只能向 inbox 提交反馈，研究目标由研究控制器以版本比较方式更新，避免两个 agent 同时覆盖状态。后续实现需确认 dsh SDK 的消息注入、事件订阅、取消和会话恢复接口，再决定通过现有服务还是自定义插件接入。

增加验收：休息期间零后台研究调用、SETTLING 期间复评确实执行、条件提前触发可唤醒、重启恢复等待、目标变更使旧脚本失效、脚本错误可见，以及研究中对话响应和用户消息只消费一次。

## 行情与触发规则

实现前依据 Bitget 当前官方文档确定产品目录、行情和 K 线接口及参数，并做真实公共接口冒烟验证。优先使用无需鉴权的市场数据接口；股票相关产品仅在接口返回的品种目录验证后允许加入。行情中记录交易所时间、采集时间、品种和类别。

默认使用已收盘的 1 分钟 K 线：最近 5 分钟收盘价绝对变化达到 2%，或最新已收盘分钟成交量达到此前 20 根同口径 K 线平均值的 3 倍时触发。样本不足、基准成交量为零、时间断档或过期时不计算对应信号。门槛属于可调的工程默认值，不代表有效交易策略。

事件标识由市场类别、品种、规则和收盘时间组成，数据库唯一约束防止重复入队。同品种同规则默认 30 分钟研究冷却，重复信号保留记录但不重复调用模型。复查时间持久化，默认一小时后对未解决观察项重评，计入同一预算并去重。

## 输出与运行

使用配置文件维护自选列表、规则和预算；提供检查配置、单轮采集、持续运行和查看状态命令。首版通知输出到终端和本地 Markdown 文件，日报在 Asia/Shanghai 每日 08:00 生成前一自然日汇总，使用日期唯一键避免重复。未配置外部消息渠道前不向外发送。

SQLite 保存行情摘要、事件、研究、复查任务和日报状态。网络错误指数退避，尊重限流响应；某个品种失败不影响其他品种。提供心跳时间、最后成功采集时间和错误摘要，能够区分进程在线与行情正常。进程关闭时停止接收新研究并安全保存进度。部署主机必须保持运行，电脑睡眠期间不会采集；恢复后显式记录数据缺口。

## 验收

测试规则边界、未收盘数据排除、缺失和过期行情、品种类别区分、事件去重、冷却、预算、dsh 超时和非法输出，以及重启后的待办恢复。真实 Bitget 冒烟测试验证配置品种与数据结构。模型凭据可用时完成一次真实 dsh 研究，否则明确记录模型端到端验证尚未完成。重启后同一事件不能重复生成本地研究通知。
