# 长期资产追踪分析框架：结构解读

配套图：[长期资产追踪框架 SVG](long-term-asset-tracking-framework.svg)。图将原始英文框架整理为“证据入口 → 七层分析 → 状态判定 → 本轮输出 → 下轮复核”的闭环。

## 核心判断

这个框架研究的不是下一根 K 线，而是一个资产的长期正反馈是否出现、得到确认、过热、背离或衰退。它把金融环境放在前面，先用跨资产检查大环境，再考察资产自身的兑现能力、产业投资、价格与市场愿意支付的估值，最后比较本轮与上轮证据。价格是市场反馈，不是基本面的替代品。

分析顺序应是：宏观金融环境 → 跨资产锚点 → 基本面与客户/行业 CapEx（同时检查价格结构）→ 叙事与估值 → 反身性/泡沫 → 内外部背离 → 相比上轮的边际变化。宏观中的“降息”必须区分通胀回落和增长崩塌；黄金、原油、BTC 等不能按单一方向机械解释。跨资产背离要观察持续性，不能因一天的偏离就断言换挡。

每个可比序列都要同时看水平、变化方向及变化速度。季度营收和 CapEx 应按相同会计口径及可比期间计算；价格、宏观日度数据和季度财报不能混作同一采样频率。状态变化应由多条独立证据支持，并保存“原判断、证据变化、反证、失效条件、下次复核点”。八种状态是互斥的**本轮主标签**，不是必经的线性生命周期；泡沫、跨资产背离等仍应作为并行风险标记保留。

## 框架的强项与需要补的判定规则

强项是将“价格上涨”拆成流动性、盈利兑现、客户投资、估值扩张等来源，且明确区分正反馈与脱离基本面的叙事扩张。它要求每轮写出相对上次的边际变化，天然适合长期追踪，而非重复生成技术分析。

原文同时要求每轮从八个状态中选一个，又要求缺数据时承认不可用。两者在关键基本面缺失时会冲突。实际系统应增加“证据不足/无法判定”状态，并将置信度与证据覆盖度分开；不能凭量价把资产判为“完整飞轮”。此外，状态条件需要资产类型适配：半导体设备可看客户 CapEx 和 WFE，ZEC 没有公司营收、EPS 或客户 CapEx，应改看可核查的链上使用、网络安全/算力、发行与供给、流动性、开发及采用等数据，并保留原框架的宏观—跨资产—价格—叙事—背离逻辑。无法可靠采集的维度应持续显示为缺口。

可执行的追踪节奏是：短周期只侦测候选变化；日/周级别确认结构；财报、政策、行业投资等事件触发专项复核；定期重估长期状态；重启时先补中断区间并与上次判断对照。研究不应由固定的每日调用次数定义。
